# 账号与网关教程计划

## 场景与当前基线

用户登录后查看自己的 Sub2API 余额和消费记录，后续生成与充值也使用同一可信身份。

项目基线与检查结果见 [教程索引](../README.md)。现有 [`users`](https://github.com/JeanphiloGong/image-studio/blob/main/db/001-initial.sql) 只有本地 ID、邮箱和创建时间；没有会话、网关绑定或余额查询接口。首页“登录”链接仍指向 `/`。邮箱相同不证明拥有某个网关账户。

已核对私有参考项目 `user-portal` 的 `HTTPClient.GetUser`（读取 `/api/v1/admin/users/{id}`）与 `ListUsage`，以及其 Sub2API 管理合同。这是服务端实现参考，尚未验证实际部署网关。

## 版本

| 版本                 | 前置                                       | 能力变化与集成                                                | 排除                                   | 检查和复用                                                                                   |
| -------------------- | ------------------------------------------ | ------------------------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------- |
| V0：登录并查本人额度 | 后端／数据库选型、登录与可信绑定方式已确定 | 从无可信身份到会话、持久化绑定、本人余额／用量 API 和最小页面 | 公共计费账号、本地余额、自动按邮箱关联 | 教程提供两个用户的请求脚本及测试网关；Alice 只能查 Alice，失败显示不可用；生图／订单复用绑定 |
| V1：真实网关核对     | V0、实际网关读取合同和部署配置             | 接入真实余额／用量并核对单位与分页过滤                        | 充值、生图密钥自动创建                 | 按正文联调清单核对测试用户和网关记录一致，浏览器响应无管理员凭据；供真实生成与充值使用       |

本模块不必为字段声明单独划一个“建模版本”。你先明确归属和绑定信任来源，随后在 V0 内完成能够证明用户隔离的最小集成。

## 编写正文前的选择

需要确定登录方式、已有网关账户如何证明归属、新用户由谁创建账户，以及重复绑定的规则。当前核心任务模型不依赖这些选择；账号 V0 的正文则必须先解决。

采用 Go 建议时，新增目标是 `server/internal/accounts/`、`server/internal/gateway/`、`server/migrations/` 和必要 HTTP 入口；这些目录当前均不存在。前端调用者仍是项目根目录的 `src/routes/`，不为了教程先整体移动到 `web/`。具体符号、迁移编号和请求入口在选定本版本时结合当时源码细化，当前不是可直接实施的逐文件清单。

## 验收边界

查询接口只从服务端绑定解析网关用户，不能接受浏览器任意指定的网关 ID。Alice 请求 Bob 的资料应被拒绝；未绑定或失效会话不访问网关。余额是查询结果而非可修改本地余额；网络失败与真实零余额有不同结果。

V0 正文需同时交付会话／绑定所需迁移、本人请求脚本和本地测试网关，读者不需要先准备真实 API 密钥。回归生图模型及原型检查。V1 再单独进行真实网关联调。

`commit_when`：所选版本包含的身份、调用者、存储和隔离检查全部完成，且未暴露凭据；这是未来可提交条件，本次不执行提交。
