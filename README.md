# Image Studio 实施教程路线

更新日期：2026-10-25。以现有 Image Studio 项目为起点，先由你理解并实现核心业务规则，再让 agent 按已验证的规则补齐存储、接口、worker 和页面。

本目录包含四个模块的计划，以及首篇已逐步复跑的 [生图 V0 完整教程](02-generation/V0-任务状态与不确定结果.md)。其余版本仍处于计划阶段，产品业务代码未实施。模块用于组织知识，版本用于描述每一步能验证什么；不要求每个目录对应独立服务或一套架构层。

## 从哪里开始

先读 [Image Studio 产品规格](https://github.com/JeanphiloGong/image-studio/blob/main/docs/PRODUCT-SPEC.md)，再读 [核心建模与交接](00-核心建模与交接.md)，然后照着 [生图 V0：任务状态与不确定结果](02-generation/V0-任务状态与不确定结果.md) 完成第一个核心模型。完成后再进入账号、持久化和真实调用。

你不必先实现所有模块。每完成一个核心模型及其边界测试，就能交给 agent 扩展该模块；后续支付、订阅的产品选择仍由你确定，不能让 agent 从字段名字自行猜测。

## 版本路线与依赖

版本编号在模块内使用，依赖以“模块 + 版本”表达。下表的命令／操作是未来教程交付完整代码与检查入口后的验收，不表示当前已经存在这些入口。

| 版本                 | 从哪里开始                                         | 新增能力与包含的集成                                                 | 本版不承诺                             | 立即验收与下一步复用                                                                             |
| -------------------- | -------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 生图 V0（当前选定）  | 现有 schema 只有状态字符串                         | 单个真实任务模型约束合法转换，拒绝不确定任务重发                     | HTTP、数据库、真实生图、并发安全       | 运行正文提供的状态测试：超时到 `uncertain`，再次开始被拒绝且状态不变；后续 worker 复用同一规则   |
| 账号 V0              | 当前没有会话与绑定；后端选型、登录／绑定方式已确定 | 登录、可信绑定、本人余额和用量查询、必要存储与页面                   | 本地消费余额、图片调用                 | 按正文脚本以 Alice/Bob 身份请求：仅能读取本人；网关失败返回不可用；供生图与充值复用身份          |
| 生图 V1              | 生图 V0 + 账号 V0；持久化方案已确定                | 用户幂等提交、原子认领、执行标记、任务查询与恢复；以本地测试上游检验 | 实际模型可用性、真实费用               | 正文并发／重启检查：同用户同键只一个任务和一次测试调用，结果不明不重发；真实调用复用此链路       |
| 生图 V2              | 生图 V1 + 已核实的用户凭据和图片 API 合同          | 真实用户身份调用、保存图片、本人下载、页面状态与用量关联             | 自动补余额、上游严格一次执行保证       | 本地回归后单独联调：本人生成下载，用量归本人；远端成功但本地保存失败不再次生图；供上线使用       |
| 订单 V0              | 有关付款和履约的产品规则已明确，后端基础可运行     | 订单快照、付款匹配与履约身份的核心规则，可独立测试                   | 真正验签、DB 幂等、真实入账            | 正文规则测试：金额／币种不匹配不变为已付，同订单生成同一履约标识；支付链路复用                   |
| 订单 V1              | 订单 V0 + 账号 V0 + 已核实网关幂等合同和支付渠道   | 创建支付、签名校验、事务、唯一约束、直接充值、核查恢复和订单查询     | 积分兑换、自动退款、自动续费           | 正文集成脚本重复／并发通知并中断响应：一份购买权益只到账一次，未确认可核查；订阅复用同一订单履约 |
| 订阅 V0              | 周期、续购与取消规则已确定，后端基础可运行         | 期间有效性及取消规则，固定时间可验证                                 | 月度扣款、额度写入                     | 正文时钟测试覆盖开始／结束边界、取消与续购；V1 复用期间语义                                      |
| 订阅 V1              | 订阅 V0 + 订单 V1                                  | 购买一个周期、幂等开通、权益履约、本人查询和取消                     | 自动续费／自动月度发放、自动退款清余额 | 正文重复订单检查：一次开通／一次权益到账；取消遵守选定规则且不改网关余额；形成首版商业闭环       |
| 上线版本（后续规划） | 上述闭环及测试已完成                               | 预算／并发控制、持久化、HTTPS、备份恢复、审计和异常核查              | 无条件自动重试、不受限公开试用         | 按上线演练执行重启、备份恢复、预算闸门与异常核查；此后再规划自动续费                             |

建议学习顺序是生图 V0 → 账号 V0 → 生图 V1/V2；支付与订阅的核心建模可提前学习，完整业务接入按依赖推进。固定合同和安装环境属于准备工作，不单独冒充一个业务版本。

## 当前计划的边界与交接

当前选定“生图 V0”，因为它既是你能亲自实现的最小模型，也能独立检验一个关键业务规则，无需先搭 HTTP 或支付。完整步骤和冻结条件见该模块计划。

后端选型尚待确认。首篇生图 V0 已按推荐路线写成 Go 教程并在隔离副本验证，这不表示产品工作树已切换技术栈。后续持久化仍以 Go + PostgreSQL 为建议；如果选择继续使用 TypeScript，先调整相应正文和检查，不同时维护两套实现。生图 V0 本身不需要数据库。

已确认且所有模块必须遵守：页面独立设计；余额直接来自 Sub2API；消费由绑定用户的网关调用计费；订单直接给该用户充值；没有平台积分或本地预占；超时先核查；订阅记录不等于自动续费。

尚需按依赖解决：登录与可信绑定方式、用户调用凭据、当前网关幂等与查询能力、支付商户与商品参数、订阅取消／续购语义。它们不会阻止整理本目录，但对应正文不能替用户做出影响业务的选择。

生图 V0 正文已包含可直接运行的检查，读者无需先自行补测试。接下来先亲自完成并理解这个模型，再确认账号 V0 的登录与可信绑定机制，细化后续教程。教程可验证、本人模型完成、持久化已验证、生产可用是不同状态，应分别报告。
